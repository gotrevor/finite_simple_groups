## 🧠 Reusable gotchas flushed this lap (worth a memory/corpus entry)

- **Anonymous SL/Sp constructor loses the type synonym.** `(⟨M, h⟩ : SpecialLinearGroup n F)`
  has type that whnf-unfolds to the raw subtype `{A // A.det = 1}`, so `= 1` / `ext` fail to
  find the `Group`/`One` instance (`OfNat {A // …} 1` / `Group {A // …}` synth failure). Fix:
  get the `= 1` goal from the EXISTING goal via `convert Subgroup.one_mem _`, or `revert` the
  dependent `.det = 1` proof, `rw` the matrix to `1`, `intro` it back, then `convert`.
- **`set Jm := X with hJm` blocks lemma rewrites.** Lemmas stated about `X` won't fire on the
  folded `Jm`; either `rw [hJm]` first or `have hfact : <goal about Jm> := by rw [hJm]; exact <lemma>`.
- **`Matrix.J`'s `-1` is "atomic" for `rw [neg_neg]`** — `rw [neg_neg]` fails on `-(-1)=1` but
  `exact neg_neg _` succeeds (defeq, not syntactic).
- **dotProduct/`sumElim_dotProduct_sumElim`/`dotProduct_comm` are ROOT-level**, not `Matrix.…`;
  most `vecMulVec`/`mulVec`/`transpose` lemmas ARE `Matrix.…`. Under `open Matrix`, just use
  unqualified names for both.
- **char-2 trap:** proving `vᵀ M v = 0` for skew-symmetric `M` via `vᵀMv = (vᵀMv)ᵀ = -vᵀMv`
  only gives `2x=0` — useless over `ZMod 2`. Use the ALTERNATING (block / zero-diagonal)
  structure instead. (`spForm_self` is the worked example.)
- **`Basis`/`finrank` etc. live in `Module` namespace** now (`Module.Basis.sumExtend`); add
  `open Module` (the cardinality lemmas like `Module.finrank_eq_card_basis` stay qualified).
