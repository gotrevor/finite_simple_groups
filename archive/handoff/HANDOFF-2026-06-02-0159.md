## 🧠 Context to carry forward
- **The order-pin sweet spot (the session's real finding, load-bearing):** pinning
  `Nat.card carrier = order` is a cheap faithfulness anchor *only* for **opaque** carriers —
  a wrong value is merely unfaithful, never contradictory. For the **real mathlib-typed**
  carriers (`PSL n q := Matrix.ProjectiveSpecialLinearGroup …`, `PSp` a quotient) the same
  pin is a **correctness hazard**: it asserts "my formula = the true cardinality", and a wrong
  formula *contradicts reality* and makes CFSG unprovable for genuine instances. So **do NOT
  extend the order-pin to the Lie-type families.** The sporadic pin worked because it sits in
  the sweet spot (opaque carrier + high-confidence constant), not as a general pattern. Flushed
  to memory as `lean-order-pin-opaque-vs-real-carrier`.
- **The ATLAS orders are documented guesses, not verified.** `Name.order`'s 26 values were
  reconstructed from memory (~95% on small ones, ~85% on the 9 large factorizations). The
  honest discipline (Trevor endorsed it for sporadics): factored form + confidence-tagged
  docstring + an RFI. The cross-checks added this session (Mathieu chain, Monster divisibility)
  are *internal* consistency tests that passed — they raise confidence but don't replace the
  external ATLAS check. **`RFI-ATLAS-sporadic-orders.md`** at repo root requests that external
  cross-check (any web-capable process / host session can fulfill it).
- **The two-debt model** (use this vocabulary, Trevor likes it): *proof debt* (unproven
  implications — axioms pay this) vs *definitional debt* (`opaque` carriers — undefined
  objects). The order-pin chips at definitional debt without de-opaquing.
